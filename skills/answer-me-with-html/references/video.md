# 讲解视频（am video，3Blue1Brown 风格）

当 SKILL.md 第 7 节把你送到这里时，阅读本文。`am` 指的是 SKILL.md 第 2 节中完整的 `node ".../scripts/am.mjs"` 命令；请把路径完整写出来，因为本文件中 `${CLAUDE_SKILL_DIR}` 不会被替换。

视频草稿的格式与页面草稿相同，但多一条规则：以 `>` 开头的行是旁白，每行一拍。

````bash
am video - --no-open <<'AM_EOF'
---
title: TCP 三次握手
subtitle: 为什么是三次
---
> 开场旁白（可选）。

## 两端都在等待
```sequence
Client -> Server: SYN
Server -> Client: SYN-ACK
Client -> Server: ACK
```
> 首先客户端发送 SYN，请求建立连接。
> [Server] 用 SYN-ACK 回应。
> 客户端回复 ACK，连接就此建立。
AM_EOF
````

- 一个 `## ` 就是一个场景。在场景中放一个组件（或一个表格、一个列表）作为画面，并在其下方写 2–5 行旁白。
- 当第 N 行旁白播放时，画面显示第 N 步。在 flow / er / sequence / tree 中，每一行源码就是一步；timeline、limits、表格行和列表项则按条目逐步推进。因此组件的行顺序就是讲解的顺序。当旁白行数多于步骤数时，多出来的开头几行作为开场，不展示新内容。
- 在旁白中写 `[name]`：镜头会拉近并高亮该名称对应的节点或参与者。名称必须与组件中的写法一致。
- 相邻场景中同名的节点会平滑移动到新位置。为了让观众持续跟随同一个对象，请在下一个场景中复用相同的名称。
- 每个视频 3–6 个场景，每行旁白一到两句话。
- 旁白是朗读出来的，所以要写成口语，就像面对面给人讲解一样：像 `你看`、`那问题来了`、`我们换个角度看` 这样的过渡语都可以用，角色的"台词"要加引号。不要写成手册腔（`客户端发送 SYN 报文以请求建立连接`）。句子长度仍受 STE 检查约束。
- 外观默认遵循设置中的主题（通常是蓝图绘图风格）。当用户想要"那种暗色 3b1b 风格"时，在 frontmatter 中写 `theme: 3b1b`。
- 旁白语音：默认是 `--voice auto`：设置了 `ELEVENLABS_API_KEY` 时用 ElevenLabs，否则用系统 TTS（macOS say），两者都不可用时只显示字幕。当用户说"不要声音"时，加上 `--voice off`。当用户运行本地 OpenAI 兼容的语音服务并设置了 `AM_TTS_URL` 时，使用 `--voice local`。
- 输出是 `~/.answer-me-with-html/videos/` 下的单文件播放器页面（内嵌音频）。播放器在控制条上方带有一条章节条（点击某个标签可跳转到该场景）、一个速度按钮（0.5× 到 2×）以及一个导出按钮（⤓），后者会在浏览器中编码同一个视频并下载，进度显示在按钮上。当用户想要在页面旁边得到一个视频文件时，加上 `--mp4` 生成 MP4（需要 ffmpeg，耗时约为视频时长的 1.3 倍）。没有 ffmpeg 时，改用 `--webm`：页面自行编码 WebM（VP9 + Opus）；其耗时取决于页面有多少内容在动（实测：11 秒的草稿用了 28 秒，2:27 的讲解视频用了 13.5 分钟）。两者都需要 Chrome 和 Node.js 22+。导出按钮需要安全上下文（本地文件或 `localhost`）：通过纯 HTTP 提供的页面无法使用 WebCodecs。为此播放器页面会增大约 19 KB。
- 完整语法：`am help video`。在终端中，用一句话加上播放器页面链接（以及 MP4 链接）回复，写法如 SKILL.md 第 2 节第 5 步所述。
